# Фикстуры для оценки распознавания

`fixtures/receipts/` исключена из git: там реальные чеки с личными данными.
Скрипт `npm run eval` прогоняет их через `GeminiParser` и сравнивает с эталонами.

## Как добавить кейс

1. Положите файл в `fixtures/receipts/`: `.jpg`, `.jpeg`, `.png`, `.webp` или `.pdf`.
   Имя файла без расширения — имя кейса: `evroopt_2026-10-05.jpg` → кейс `evroopt_2026-10-05`.
2. **Несколько картинок одного документа** (длинный чек частями, заказ на нескольких скриншотах):
   `<кейс>_1.png`, `<кейс>_2.png`, … — файлы с общим префиксом и номером после `_`
   склеиваются в один кейс `<кейс>` (по порядку номеров). Одиночный `foo_1.jpg` без `foo_2.*`
   остаётся отдельным кейсом `foo_1`.
3. Сгенерируйте черновик эталона и **проверьте его руками** по фото:
   ```
   npm run eval -- --only <кейс> --write-expected
   ```
   Существующий эталон не перезаписывается без `--force`.

## Формат `<кейс>.expected.json`

```json
{
  "doc_type": "store_receipt",
  "total": 23.45,
  "store_name": "Евроопт",
  "items": [
    { "name": "Молоко Савушкин 3,2% 0,9л", "total": 2.39, "category": "groceries" },
    { "name": "Пакет", "total": 0.21, "category": "groceries" }
  ]
}
```

- `doc_type` — обязателен: `store_receipt` | `erip` | `online_order` | `not_purchase`.
- `total` — фактически списанная сумма (с комиссией), в рублях. Для `not_purchase` — `null`.
- `store_name`, `items` — необязательны; без `items` позиции не оцениваются.
- `items[].total` — итог позиции после скидки, **как его сохранит бот**: комиссия ЕРИП /
  сервисный сбор уже прибавлены к самой крупной позиции. Если позиций нет (ЕРИП без
  разбивки) — одна позиция на всю сумму.
- `items[].category` — код категории из `src/domain/categories.ts` (необязателен).

## Метрики

- **тип** — совпадение `doc_type`;
- **итог** — точное совпадение до копейки;
- **позиции** — доля эталонных позиций, нашедших пару: итог совпадает (±1 коп.),
  название похоже (биграммы после `normalizeName`);
- **категории** — доля совпавших категорий среди найденных пар.

Отчёт печатается по каждому кейсу и сводно по типам документов. Ошибка распознавания
считается промахом.

## Опции

```
npm run eval                              # все кейсы
npm run eval -- --only order1             # один кейс
npm run eval -- --dir /path/to/receipts   # другая папка
npm run eval -- --delay 10000             # пауза между запросами, мс (по умолчанию 6000)
npm run eval -- --timeout 60000           # таймаут запроса, мс (по умолчанию 25000, как в боте)
```

Ключ `GEMINI_API_KEY` и модель `GEMINI_MODEL` берутся из переменных окружения,
затем из `.dev.vars` / `wrangler.jsonc`. Бесплатная квота Gemini — порядка 100 запросов
в день и ~10 в минуту: каждый кейс — один запрос.
